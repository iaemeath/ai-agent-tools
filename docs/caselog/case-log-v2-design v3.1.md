> **依据**：以《Case-Log 需求规格 v1.1》为唯一依据；对需求层四空洞（回顾覆盖策略 / 度量错位 / R5 质量闸门 / Q5 拆分）以架构决策形式补全，标记 🔶 待确认

## 0. 设计原则（从需求推导，架构的一切取舍都回到这五条）
1. **巩固在大脑，系统是中转站**——每处设计都自问：这个动作是否把认知加工从人手里拿走了？拿走即违规。
2. **AI 全程后置**——AI 只出现在「人完成主动加工之后」的校对/润色/补全环节。
3. **时间线是唯一消费入口**——无检索、无搜索框、无 AI 注入。
4. **每日 25 分钟预算红线**——超出预算的仪式一律不做；交互目标 = 把「处理+回顾」压进 25 分钟。
5. **人工确认唯一写入通道**——无 hook、无自动捕获、无自动注入。
6. **简单优先**——单用户、单机、内网，能省则省。

```
┌─────────────────────────────────────────────────────────────┐
│                    可视化页面（唯一消费入口=时间线）              │
│   时间线视图 │ 回顾视图 │ 候选勾选 │ 终审/编辑 │ 导入导出        │
└──────────────────────────┬──────────────────────────────────┘
                           │
                    ┌──────▼───────┐        ┌──────────────┐
                    │  MCP server  │◄──────►│ 本地/内网 LLM  │
                    │ (Python)     │  AI 后置│ (校对/润色/补全)│
                    └──────┬───────┘        └──────────────┘
                           │
        ┌──────────────────┼───────────────────┐
   ┌────▼────┐      ┌──────▼──────┐      ┌─────▼──────┐
   │knowledge.db │      │ normalized/   │      │ archive/    │
   │3 实表,纯关系  │      │ 规范化会话流    │      │ 原始转录归档  │
   └─────────┘      │ 落盘保留       │      │ 按月 gzip    │
                    └──────▲──────┘      └────────────┘
                           │ ETL 提取（每日）
                    ┌──────┴──────┐
                    │ 原始转录（原地只读） │
                    │ sess_*/agent_*/    │
                    │ transcript.jsonl   │
                    └─────────────────────┘
```
**关键点**：整个系统只有 4 个可执行组件（ETL、MCP、页面、本地 LLM）；数据只有 3 张表 + 2 个文件目录。无向量、无全文索引、无检索工具、无复习算法调度。

## 3. 数据设计
### 3.1 逻辑模型（3 张表，SQLite 纯关系表，无虚表无触发器）
```
scenarios（情景：唯一知识单元）
  id / uuid / title / keywords(展示用,不建索引)
  content（症状/环境/排查含弯路四段式/根因/修复/验证/经验小结）
  category / source(manual|review)
  edited_count / edited_at          ← R7 改写留痕（轻量标记）
  created_at / updated_at / deleted_at(软删,唯一状态位)

scenario_sessions（溯源指针：行式,天然 append）
  scenario_id / session_id / agent_id
  transcript_path(相对) / seq_range("120-480")
  noted_at                          ← 跨日追加 = 插入新行(R10)
  （不设 UNIQUE，允许同会话多区间行并存）

review_log（回顾记录：Q5 处置 + Q6 度量的数据源）🔶 新增
  scenario_id / reviewed_at / outcome(remembered|forgotten|conflict)
  recalled_note(回忆要点,可选) / note
```
**为什么加 review_log**（对 v1.1「两表」的补全）：Q5 的「标记没想起来」「记录冲突」、Q6 的「想起来的比例」都需要一个落点；它只记录**人已做的回顾动作**，不驱动任何调度，不违反 N2。

### 3.2 keywords 的定位（R2 裁撤后）
keywords 不再承担检索职责，**降级为展示字段**：时间线/回顾视图中作为标题旁的一行小字（错误码/项目名/版本），辅助人再认。不建 FTS、不进向量。

### 3.3 文件布局
```
~/.knowledge/
├── knowledge.db            SQLite（3 表）
├── normalized/
│   └── YYYY-MM-DD/<session_id>.md   规范化会话流（落盘保留,跨日追加前提）
└── archive/
    └── agents-YYYY-MM.tar.gz        原始转录按月 gzip
```

## 4. 核心流程
### 4.1 每日复盘（R1 + R5，预算 ~20 分钟处理新情景）
```
0. ETL（后台/复盘前）：扫当日转录 → 规范化会话流 → normalized/
1. 人浏览当日会话流（折叠渲染）→ 勾选候选情景（选区,sequenceNumber 区间）
2. 人写草稿（R5 强制）：对每个选区，
   凭记忆写「标题 + 经验小结」草稿，必须用自己的话
   ⚠ 防粘贴闸门：草稿与转录相似度过高 → 提示重写（🔶）
3. AI 后置（R11 本地模型）：校对/润色标题与经验小结，
   补全内容结构（症状/环境/弯路四段式/根因/修复/验证）+ 建议 keywords
   → 全部以「候选」呈现，不落库
4. 人逐项确认/采纳/丢弃 AI 产物 → 落库
```
**认知保障**：步骤 2 的「人写」是不可外包的主动加工（生成效应）；步骤 3 的 AI 产物永远可一键丢弃，不构成任何默认值。

### 4.2 滚动回顾（R1a + Q4/Q5，预算 ~5 分钟）
```
1. 回顾视图列出「今天恰好处理满 1/2/4/7/15 天」的情景（视图层计算,非调度）(Q4=🔶)
2. 人挑 1 个 → 只看标题（默认态）→ 凭记忆回忆过程与教训（可记 recalled_note）(R6)
3. 展开核对
4. 记录结果到 review_log：
   - remembered → 完成
   - forgotten  → 标记 + 可重读该情景的原始会话流 (Q5=🔶)
   - conflict   → 默认「记录为准」；可回放原始转录核对；
                   若确属记录错 → 编辑修正（触发 R7 留痕）
```
**覆盖规则**（🔶）：只保证「处理满 1/2/4/7/15 天」窗口内的回顾，15 天后不再主动回顾（接受遗忘）。此规则把「回顾的完整性」从「全量覆盖」改为「关键窗口内全量」，直接消解库增长悖论（库再大，每天到期清单只与「今天满 N 天」有关，规模恒定 ≈ 每天 ≤ 5 条）。

### 4.3 即时写入（低频高价值）
手动 `scenario_save`，**同样强制**「人先写草稿 → AI 后置校对 → 人确认」三段式，不提供 AI 代写入口。

### 4.4 改写留痕（R7）
编辑保存 → `edited_count += 1, edited_at = now`。
界面显示「已改写 N 次（最后 yyyy-mm-dd）」；「当时的事实」由溯源回放按钮（跳转原始转录对应区间）提供权威来源，与「后来的理解」（当前 content）可区分。

## 5. 组件设计
### 5.1 MCP server（Python，职能收缩为 6 个工具）
| 工具 | 职责 |
|---|---|
| `scenario_save` | 唯一写入口：含 AI 后置编排 + 防粘贴闸门 + 人确认落库 |
| `timeline_read` | 按日读取情景 + 当日规范化会话流（时间线渲染输入） |
| `review_list` | 计算今日到期回顾清单（1/2/4/7/15 天） |
| `review_log` | 记录回顾结果（outcome + note） |
| `export` / `import` | 跨机迁移（db + normalized/；转录指针悬空属预期降级） |
**明确不做**：search / 向量 / FTS / RRF / 任何查询输入。

### 5.2 可视化页面（唯一消费入口 = 时间线）
- **时间线视图**：按日分组；当日情景卡片 + 当日规范化会话流（工具调用目录式折叠）；情景卡片含 title / keywords 小字 / edited 标记 / 距到期回顾天数
- **回顾视图**：今日到期清单；默认「标题列表」态，展开是显式动作（R6）
- **候选勾选视图**：复盘第一步的选区框选
- **终审/编辑视图**：AI 产物候选逐项确认；编辑触发 R7 留痕
- 页面**不提供搜索框**，任何位置无查询输入（R3/N5）

### 5.3 ETL 规范化提取器
- 每日扫时间窗内转录 → 规范化会话流（滤 model_request 重发 + model_streaming 碎片）
- 保留：user 输入 / AI 最终回复 / thinking 路径 / 工具调用目录式折叠摘要
- 落盘保留（跨日追加的指针数据源）
- 输出统一 `normalized/YYYY-MM-DD/<session_id>.md`

## 6. 认知保障机制（本架构区别于普通 CRUD 的核心，均来自需求 R5/R6/R7）
| 机制 | 架构落实 | 认知依据 |
|---|---|---|
| AI 后置 | scenario_save 强制「人先提交草稿 → AI 才介入」；防粘贴闸门 | 生成效应：自己组织的语言记得牢 |
| 先回忆后核对 | 回顾视图默认「标题列表」，展开=显式动作 | 测试效应：主动回忆远强于再认/重读 |
| 改写留痕 | edited_count + 溯源回放 | 误导信息效应：事后信息会无痕改写记忆，系统是对抗重构的锚点 |
| 回顾记录 | review_log 留存每笔回顾结果 | 提取失败的两种语义（遗忘/冲突）需分别追踪 |

## 7. 度量（Q6，🔶 待确认）
| 类型 | 指标 | 来源 |
|---|---|---|
| 过程指标 | 每日复盘坚持率 | 应用使用记录 |
| 结果指标 | 回顾 remembered 比例（区分 forgotten/conflict） | review_log 统计 |
| **目标指标（补充）** | **独立提取测试**：每月不打开系统，凭记忆写下近期处理过的 5 个情景要点，再核对命中率 | 导出标题清单 → 离线回忆 → 核对 |
**说明**：独立提取测试直接测「对抗遗忘 + 反卸载」的目标达成（不借助系统能否独立回忆），而 remembered 比例测的是「看标题后的再认」——两个指标合起来才覆盖目标。

## 8. 待裁定项的架构决策汇总（🔶 请确认）
| 项 | 决策 | 理由 |
|---|---|---|
| Q4 回顾挑选 | a. 遗忘曲线间隔位（满 1/2/4/7/15 天各回顾一次）+ 覆盖规则「15 天后不再主动回顾」 | 近期高频巩固符合遗忘曲线；覆盖有界消解库增长悖论 |
| Q5 回顾不连贯 | 拆分：forgotten→标记+可重读；conflict→记录为准+回放核对+修正留痕 | 两种失败语义不同，处置不同 |
| Q6 成功度量 | 坚持率（过程）+ remembered 比例 + 独立提取测试（目标） | 目标与度量对齐 |

## 9. Non-Goals 的架构落实
| Non-Goal | 架构落实 |
|---|---|
| N1 非自动记忆 | 无 hook、无捕获、无注入；scenario_save 是唯一写入口且必经人确认 |
| N2 无知识治理算法 | 无复习调度、无自动提醒、无版本链/熔断/失效/recency；回顾挑选是视图层计算（人执行） |
| N3 无语义层 | 无概念库/图谱/画像；keywords 降为展示字段 |
| N4 无团队 | 单用户单机；export/import 承担跨机 |
| N5 无检索 | 无向量/FTS/RRF/搜索框；时间线为唯一入口 |

## 10. 风险与权衡
| 风险 | 缓解 |
|---|---|
| 每日仪式脆弱（缺一天即可能崩） | 缺失恢复：回来时从「今日到期清单」继续，不补历史、不追责 |
| 无检索 → 「想找却翻不到」 | 演进档案记录「时间线翻找失效」事件；达到阈值（如 3 次/周）触发重议检索需求 |
| 人敷衍写草稿（反卸载失效） | 防粘贴闸门 + 「草稿可空但不可粘贴」的硬规则 |
| 情景积累 → 时间线变长 | 时间线按「处理日」归档折叠；旧情景默认折叠为标题行 |
| 改写消解事实 | 改写留痕 + 溯源回放（当时事实的权威来源在原始转录，不在 content） |

## 11. 实施分期（简单优先，3 期）
| 阶段 | 内容 | 验收点 |
|---|---|---|
| **Phase 1** | 建库（3 表）+ MCP（scenario_save 含 AI 后置 + timeline_read）+ ETL | 一条情景经「人写→AI校→确认」落库，时间线可见 |
| **Phase 2** | 复盘工作流：候选勾选 + 终审编辑（含 R7 留痕）+ 回顾视图（含 review_log） | 一次完整每日复盘 ≤25 分钟 |
| **Phase 3** | 时间线体验打磨（折叠/归档）+ 独立提取测试 + 导入导出 | 连续 2 周坚持 + 完成一次独立提取测试 |
