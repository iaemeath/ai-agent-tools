# Case-Log 需求规格（v1.1）

> **文档性质**：需求确认文档（v1.1，2026-08-26，含两轮问答裁定）
> **用途**：方案的唯一依据；逐条确认后据此修订方案（v3.1+）
> **标记**：✅ 已拍板 / ❌ 已裁撤 / ❓ 开放待裁定

---

## 1. 背景

与 AI 结对工作成为日常，对话中反复出现有价值的问题解决过程（排障、搭建、决策、踩坑），但这些过程随会话结束而消散。同时已出现认知卸载征兆（谷歌效应）：大脑越来越倾向「等 AI 回答」而非自己思考。需要一套系统把对话沉淀为可复盘的情景记录，**以对抗遗忘、并恢复主动思考的提取通道**。

## 2. 系统一句话

**个人复盘工作台：每日以「人先写、AI 后校」的方式处理与回顾情景记录，对抗遗忘、对抗认知卸载；巩固发生在我的大脑，系统只承载记录与时间线。**

## 3. 核心理念（✅ 已裁定）

**最终目的是从与 AI 的对话中学习；因为学习会遗忘，所以建立情景记录用于对抗遗忘。** 对抗遗忘走**巩固为主、检索兜底**路线——后来检索层整体裁撤（见 R2），系统全押巩固路线：

- **巩固路线**：复盘过程本身让大脑少遗忘（每日处理 + 滚动回顾），记录是巩固的素材
- **反认知卸载**：AI 全程后置——人先勾选、先凭记忆写草稿，AI 才校对补全；防止「知道能查到/能让 AI 写」降低大脑编码投入
- **遗忘对象**：经验/规律与过程/弯路**同等重要**

## 4. 需求条目

### 4.1 每日复盘（核心需求，✅ 已裁定）

| 编号 | 需求 | 说明 |
|---|---|---|
| **R1** | **每日复盘**：以天为单位，每晚 ~25 分钟；动作 = 完整处理 1 个新情景 + 回顾之前处理过的情景 | 节奏从周度批量改为每日（遗忘曲线：细节衰减快，巩固依赖「还能唤起细节」） |
| **R1a** | **滚动回顾**：每日回顾此前处理的情景——先只看标题凭记忆回忆（提取练习），再展开核对 | 回顾挑选规则待裁定（Q4） |
| **R5** | **提炼由人写，AI 全程后置**：人先勾选候选选区、先凭记忆写标题与经验小结草稿（哪怕粗糙），完成后 AI 才出现做校对、润色、补全 | 生成效应不可外包；AI 介入时点 = 全程后置（浏览辅助也不先行） |
| **R7** | **改写留痕**：情景记录被编辑修正时留下改写痕迹——「当时的事实」与「后来的理解」可区分 | 对抗记忆改写 |

### 4.2 记录与溯源

| 编号 | 需求 | 说明 |
|---|---|---|
| **R4** | **溯源**：每个情景挂原始会话指针（session + sequenceNumber 区间），可回放真实过程 | |
| **R8** | 原始转录原地只读；ETL 规范化会话流**落盘保留**（每日复盘阅读、勾选的输入） | |
| **R10** | 跨日情景可**追加**会话指针（append 语义，多指针行并存） | |
| **R11** | AI 环节（校对/补全）走本地/内网模型，转录与会话流不出内网 | |
| **R9** | 导入/导出（跨机迁移，db + normalized/） | |

### 4.5 约束

| 编号 | 约束 |
|---|---|
| **C1** | 单用户、单机、内网 |
| **C2** | 写入只经人工确认；无 hook、无自动捕获、无自动注入 |
| **C3** | 每日 ~25 分钟（周合计 ~3 小时，接受略超原 2~3 小时预算，换取巩固质量） |
| **C4** | 消费方式：时间线浏览（无搜索框、无 AI 检索） |

## 5. Non-Goals

| 编号 | 不做的事 |
|---|---|
| **N1** | 自动记忆系统（被动捕获 / 会话注入 / hook 管道） |
| **N2** | 知识治理（复习流算法、失效治理、版本链、熔断、recency）——滚动回顾由人执行，不建算法调度 |
| **N3** | 语义记忆层（概念库 / 知识图谱 / 用户画像） |
| **N4** | 团队功能 |
| **N5** | **检索系统（向量 / FTS / RRF / 搜索框）**——v1.1 新增裁撤项 |

## 6. 技术影响注记（供方案 v3.1）

- SQLite 回归**纯关系表**：scenarios + scenario_sessions 两张表，无虚表、无触发器同步
- bge-small-zh ONNX / vec0 / FTS5 / RRF **全部下岗**
- MCP server 职能收缩为：`scenario_save`（含 AI 后置校对编排）+ 时间线读取
- 可视化页面核心 = 时间线视图（会话流折叠渲染 + 选区勾选）+ 回顾视图 + 终审编辑
- ETL 规范化提取器保留（每日复盘的输入）
